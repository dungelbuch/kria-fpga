# KR260 Vivado project

Vivado 2025.2 project for the Kria KR260 Robotics Starter Kit. The block design
streams test data from the PL into the PS DDR:

```
dummy_data_gen --AXIS--> ram_writer --AXI--> SmartConnect --> PS S_AXI_HP0_FPD (DDR)
PS M_AXI_HPM0_FPD --> SmartConnect --> AXI-Lite registers of all cores and GPIOs
```

All user cores run on `pl_clk0` (`PL_CLK_FREQ` in [src/parameters.tcl](src/parameters.tcl))
and take their reset from one bit of an AXI GPIO reset vector, so software
configures a core first and then releases it from reset. A second AXI GPIO
drives the user LEDs UF1 and UF2.

## Layout

```
install/            Vivado 2025.2 installer script and config
ip_cores/           User IP cores, one folder per core (see below)
  xlibs/            Shared VHDL testbench utilities and testbench template
scripts/
  settings.tcl      Project name, part, board, IP vendor settings
  core.tcl          Packages one IP core into build/cores/
  core_sim.tcl      Creates the simulation project for one IP core
  project.tcl       Creates the Vivado project and block design
  synth.tcl, impl.tcl, bitstream.tcl, export_xsa.tcl
src/
  parameters.tcl    Clock, BRAM size, reset indices, AXI base addresses
  bd/kr260_ps.tcl   Block design
  hdl/              Top level and other HDL files, added automatically
  constraints/      *.xdc files, added automatically
build/              Generated projects and logs (not tracked)
output/             kr260_ps.bit, .bit.bin and .xsa (not tracked)
```

## IP cores

| Core | In block design | Simulation | Description |
|------|-----------------|------------|-------------|
| [axis_dummy_data_generator_v2_0](ip_cores/axis_dummy_data_generator_v2_0) | yes | yes | Counter or BRAM test data source |
| [axis_ram_writer_v2_0](ip_cores/axis_ram_writer_v2_0) | yes | no | Writes an AXI stream into DDR |
| [axis_lia_fir_v1_0](ip_cores/axis_lia_fir_v1_0) | no | yes | I/Q FIR low pass filter (lock-in amplifier) |
| [axis_lia_iir_v1_0](ip_cores/axis_lia_iir_v1_0) | no | yes | I/Q IIR low pass filter (lock-in amplifier) |

Cores used by the block design are listed in `CORES` in the [Makefile](Makefile),
cores with a simulation project in `SIM_CORES`. A core folder contains:

```
hdl/                HDL sources
core_config.tcl     Core properties and bus interfaces
core_ext.tcl        Optional, Xilinx IPs used inside the core
sim/                Testbench, sim_config.tcl and test_data/
```

The core name ends with its version, `axis_ram_writer_v2_0` is packaged as version 2.0.

## Build

```
make           # build everything: bitstream and XSA
make cores     # package the IP cores listed in CORES into build/cores/
make project   # create build/kr260_ps.xpr (packages the cores first)
make synth     # run synthesis
make impl      # run implementation
make bit       # write the bitstream to output/
make xsa       # export the hardware platform to output/
make gui       # open the project in the Vivado GUI
```

Each step runs the steps before it if they are missing or out of date. Logs are
in `build/logs/`. `clean`, `clean-cores`, `clean-project`, `clean-synth`,
`clean-impl` and `clean-sim` remove the respective results.

Vivado is loaded from `/tools/Xilinx/2025.2/Vivado/settings64.sh`, override it
with `make VIVADO_SETTINGS=<path>`.

The XSA in `output/` includes the bitstream and can be used as the hardware
platform in Vitis or PetaLinux.

Changes made in the GUI are not saved back to `src/bd/kr260_ps.tcl`. To keep a
block design change, update that file (or export it with `write_bd_tcl`) and run
`make clean-project && make`.

### Adding a core to the block design

1. Add the core folder name to `CORES` in the [Makefile](Makefile).
2. In [src/parameters.tcl](src/parameters.tcl), give it a new reset index, raise
   `RESET_WIDTH` and pick AXI base addresses that do not overlap the existing ones.
3. Instantiate and connect it in [src/bd/kr260_ps.tcl](src/bd/kr260_ps.tcl).

## Simulation

The testbenches read their test vectors from `ip_cores/<core>/sim/test_data/`.
These files are generated by a Python script and are not tracked. The scripts
need numpy, scipy and matplotlib; the project's `.venv` has them:

```
uv venv && uv pip install numpy scipy matplotlib     # once
.venv/bin/python ip_cores/<core>/sim/test_data/generate_test_data.py
```

Then create the simulation projects for all cores in `SIM_CORES`:

```
make sim-cores
```

This creates `build/sim_cores/<core>_sim/<core>_sim.xpr`. It is recreated when
the core's HDL, Tcl or sim files change. The repository path is passed to the
testbench as the `repo_path` generic, so the test vectors are found wherever the
repository is checked out.

Run the simulation in the GUI (Flow > Run Behavioral Simulation, then `run all`
in the Tcl console), or in batch mode:

```
source /tools/Xilinx/2025.2/Vivado/settings64.sh
vivado -mode batch -nojournal -nolog -source /dev/stdin <<'EOF'
open_project build/sim_cores/<core>_sim/<core>_sim.xpr
launch_simulation
run all
close_sim
EOF
```

To add a simulation for a core, put a testbench and a `sim_config.tcl` into its
`sim/` folder (start from [ip_cores/xlibs/tb_template.vhd](ip_cores/xlibs/tb_template.vhd))
and add the core to `SIM_CORES`. See the core's README for what its testbench checks.

## Installing Vivado

[install/install_vivado.sh](install/install_vivado.sh) installs the required apt
packages, runs the 2025.2 installer in batch mode with
[install/install_config.txt](install/install_config.txt) (Vitis Unified with
Zynq UltraScale+ MPSoC and Kria device support, installed to `/tools/Xilinx`),
installs the cable drivers and adds the Vivado/Vitis settings to `~/.bashrc`.
It uses sudo:

```
./install/install_vivado.sh [xsetup_path] [install_config_path]
```
